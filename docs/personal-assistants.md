# 我的助手（第一版）

入口是「日常助理 → 我的助手」。原有日常助理界面保留在「今日助理」页签中。

## 使用流程

1. 使用竞品研究、产品资料或演示文稿模板创建助手，也可以自定义。保存名称、工作要求和偏好不会调用模型。
2. 为助手创建项目，选择最多 30 个本地文件。系统会复制资料至独立的持久工作区；原文件不变。
3. 点击「开始对话」，输入本次工作。创建的任务使用现有执行服务，出现在正常会话列表中。
4. 返回助手首页，点击「继续对话」会打开原来的任务，不会启动新任务或自动发送“继续”。
5. 对话顶部显示助手与项目；「资料与偏好」列出本次对话实际关联的来源和设定。

偏好由用户填写，可以修改或清空。修改用于后续新对话，已有对话保留开始时的配置快照。项目之间默认使用各自的资料清单和对话；这不改变用户授权的系统工具访问权限，也不声称构成文件系统安全沙箱。

## 数据与执行

- 助手复用 `ManagedAgent` / `ManagedAgentVersion`，由 `metadata.studio.personalAssistant` 标识。
- 项目复用 `ManagedEnvironment`，其 `personalAssistantId` 绑定助手。来源文件位于用户数据目录 `assistant-projects/<uuid>/sources`。
- 新建项目先验证所有来源，再复制文件，并在数据库事务中创建工作区与环境。失败会清理新目录。
- 对话复用 `ManagedSession.backingTaskId`，首页、会话列表与助手入口都打开同一 `Task`。
- `Task.agentConfig.personalAssistant` 保存助手、版本、项目、来源和偏好的快照。续聊继续使用该会话上下文。
- 新助手的模型使用应用配置，权限由原有运行时处理。默认关闭额外记忆工具；工作要求、偏好和已有对话记录仍持久保存。
- 启动错误会保存为失败会话；已完成会话收到后续请求时，会从底层任务刷新状态。

## 本轮范围

包含创建与编辑助手、项目及资料关联、独立对话、恢复原会话、最近历史、上次会话已记录成果和中英文文案。

不包含自动提炼记忆、后台主动工作、新的团队调度器、项目资料增量管理或新安装包。项目创建后仍可通过现有聊天附件补充资料。项目侧栏展示创建时关联的清单，聊天附件继续在原有附件界面管理。

## 验证

数据库和文件复制使用临时目录中的真实 SQLite 测试；执行器使用桩，不调用线上模型。前端测试验证继续会话、项目归属、失败重试、偏好保存及版本保留。

运行 `npm run build:electron` 后执行 `node scripts/qa/personal-assistants-runtime.cjs`，可验证完整后台链路。该检查使用编译后的 ManagedSessionService、真实 AgentDaemon / Hermes 和文件读取工具，在两个独立进程之间关闭、重新打开数据库并续聊。模型响应来自本机测试服务，不读取用户账号或真实项目，也不访问线上模型。检查要求资料确实由工具读回、两轮使用同一任务、重启后历史仍传给模型、已保存对话保持原偏好。报告保存在 `artifacts/personal-assistants-2026-10-08/runtime-report.json`。

运行 `node scripts/qa/personal-assistants-preview.mjs` 可打开 `http://127.0.0.1:4327/__assistants-preview`。该入口加载真实应用组件，但使用独立浏览器示例数据，不访问用户数据库或调用模型。示例文件不能作为真实交付物使用。

详细结果和视觉检查限制见根目录 `design-qa.md`。
