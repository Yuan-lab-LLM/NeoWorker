# 任务中枢宽屏布局审计

## 结论

当前页面不是数据加载异常，而是布局约束与窗口宽度不匹配。任务中枢的智能体网格被限制为 `max-width: 1100px`，外层内容区却会铺满 Electron 窗口；在 2K 宽屏下，网格只能占左半侧，右侧因此形成大面积无功能白区。

## 当前流程健康度

1. 进入任务中枢并查看智能体总览：需重构。数据可见，但宽屏空间利用和信息层级失衡。
2. 扫描智能体状态：勉强可用。颜色和头像可以辅助识别，但卡片过密、正文过小、状态重复。
3. 选择智能体查看详情：有潜力。代码已有详情面板机制，但未选择卡片时右侧没有默认内容，也没有解释空白区域的用途。

## 主要问题

### 1. 主网格写死最大宽度

- `.mc-v2-agents` 使用 `grid-template-columns: repeat(auto-fill, minmax(300px, 1fr))`，但同时设置 `max-width: 1100px`。
- 宽屏下最多形成三列窄卡片，剩余空间不会参与布局。
- 外层 `.mc-v2-tab-content` 又是 `flex: 1`，因此空白区域被完整暴露。

### 2. 页面缺少明确的宽屏结构

- 当前既不是居中的单栏容器，也不是主列表 + 详情的双栏结构。
- 右侧看起来像详情面板占位，但没有边界、空状态或默认摘要，用户会认为页面坏了。

### 3. 信息密度过高，阅读成本偏大

- 20 多个同构卡片同时出现，在线、离线、空闲和需处理的智能体没有分组。
- 描述、任务和心跳状态字号偏小，且大量状态重复，难以快速找到真正需要操作的对象。

### 4. 语言与视觉风格不统一

- 中文产品界面中仍出现英文角色名、描述和 `OFFLINE / HEARTBEAT OFF`。
- 灰色辅助文字对比度偏低；10–12px 的文本在高分辨率 Electron 窗口里可读性不足。

## 建议方向

优先采用“智能体列表 + 详情面板”的宽屏结构：

- 左侧主区域使用响应式网格，宽屏可扩展到 4–5 列；选中智能体后收窄为 3 列。
- 右侧固定 360–420px 详情区，默认展示团队摘要、在线数量、待处理事项和最近活动；选中卡片后展示该智能体详情。
- 按“需要处理 / 正在运行 / 空闲 / 离线”分组，默认折叠离线智能体。
- 主名称使用 14px，描述与状态不低于 12px，并统一中文本地化。
- 不应通过增加背景色或装饰图解决空白，根因是信息架构和容器宽度。
